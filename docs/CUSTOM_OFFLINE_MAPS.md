# Custom offline maps for a fork

Forks do not use the upstream Speed Camera map catalog by default. The application
receives its catalog URL at build time, and the upstream URL is injected only when
GitHub is building `kill-samurai/speed-camera-offline-maps`.

A fork starts with:

- no configured catalog;
- no inherited GitHub Release map archives; and
- no inherited signing secrets.

The **Offline maps** screen explains that the fork owner must configure a catalog.
Online OpenStreetMap tiles, search, and OSRM routing continue to work normally.

## 1. Obtain an OpenStreetMap extract

Download an `.osm.pbf` extract that covers the intended region. Geofabrik publishes
country and sub-region extracts. Choose a reasonably sized bounding box inside the
extract; a larger area requires more desktop RAM, processing time, phone storage,
and routing time.

Record the bounding box as:

```text
minimum longitude, minimum latitude, maximum longitude, maximum latitude
```

## 2. Generate packages

From `tools/offline-packager`:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip osmium

python build_region.py \
  --pbf path/to/region-latest.osm.pbf \
  --output output \
  --region-id my-region \
  --region-name "My Region" \
  --bbox MIN_LON,MIN_LAT,MAX_LON,MAX_LAT \
  --version YYYY-MM-DD \
  --base-url https://github.com/OWNER/REPOSITORY/releases/download/maps-YYYY-MM-DD
```

`--region-id` may contain lowercase letters, numbers, and hyphens. The command
creates both package types and an `output/catalog.json` containing exact sizes and
SHA-256 checksums.

## 3. Validate

```bash
python validate_region.py output/my-region-full.db \
  --search "A place inside the region" \
  --origin LATITUDE,LONGITUDE \
  --weight 2
```

Validation fails if the place is missing or a route cannot be calculated.

## 4. Publish to the fork's GitHub Release

With GitHub CLI authenticated to the fork:

```bash
gh release create maps-YYYY-MM-DD \
  output/my-region-map-YYYY-MM-DD.zip \
  output/my-region-full-YYYY-MM-DD.zip \
  output/catalog.json \
  --title "Offline maps YYYY-MM-DD" \
  --notes "Offline OpenStreetMap packages generated by the included packager."
```

The tag in this command must match the tag used in `--base-url`.

## 5. Point the fork's build at its catalog

Set an Actions repository variable—not a secret—containing the new catalog URL:

```bash
gh variable set OFFLINE_CATALOG_URL \
  --body "https://github.com/OWNER/REPOSITORY/releases/download/maps-YYYY-MM-DD/catalog.json"
```

Then request a build:

```bash
./trigger-github-build.sh
```

The unmodified fork workflow builds a debug APK and uploads it as a GitHub Actions
artifact. It cannot use the upstream private signing key or publish the upstream
rolling release.

For a local Android Studio build, add this ignored entry to `local.properties`:

```properties
speedCameraOfflineCatalogUrl=https://github.com/OWNER/REPOSITORY/releases/download/maps-YYYY-MM-DD/catalog.json
```

Removing the repository variable or local property produces an app with no offline
catalog again. Previously downloaded map databases remain on a device until removed
through **Offline maps** or the app's data is cleared.
